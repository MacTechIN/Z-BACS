# Z-BACS 블록체인 가이드 — 무엇을, 왜, 어떻게 쓰고 테스트하나

| 문서 버전 | 1.0 (2026-09-19) |
|---|---|
| 근거 | [adr/ADR-0005](adr/ADR-0005-chain-selection.md), [specs/approval_protocol.md](specs/approval_protocol.md), [research/aa_passkey_spike.md](research/aa_passkey_spike.md) |
| 대상 | 블록체인을 모르는 팀원. 코드보다 "왜 이렇게 되는가"를 설명한다 |

## 0. 한 줄 요약

**우리는 블록체인을 만들거나 운영하지 않는다.** 이미 돌아가고 있는 공개 체인 **Base** 위에 우리 스마트 컨트랙트 3개를 올려 놓고, "누가 어떤 파일을 누구에게 어떤 권한으로 승인·회수했는지"를 **아무도(우리 포함) 나중에 고칠 수 없는 장부**에 기록한다. 사용자는 이 모든 것을 모른다 — 지갑도, 코인도, 가스도 보지 않는다.

## 1. 우리가 쓰는 체인: Base

| | 설명 |
|---|---|
| Base | 이더리움 위에 얹힌 **L2(레이어 2)**. Coinbase가 만든 OP Stack 체인. 블록 2초, 수수료 이더리움의 1/100 이하 |
| 왜 L2인가 | 승인 왕복이 초 단위여야 하고(UX), 건당 비용이 무시할 만해야 한다(페이마스터로 우리가 대납) |
| 왜 Base인가 | 패스키 서명(P-256)을 검증하는 프리컴파일이 활성(2026-09-19 실측 3,885 gas), 스마트계정(Kernel)·번들러(Pimlico)·페이마스터 생태계가 이미 배포됨 |

우리가 쓰는 환경은 셋이고, **코드는 동일**하다:

| 환경 | 무엇 | 언제 | 돈 |
|---|---|---|---|
| **Anvil** | 내 PC에서 도는 이더리움 시뮬레이터(Foundry). 1초 만에 뜨고, 트랜잭션마다 블록 1개 | 개발·단위 테스트·데모 | 가짜 ETH 무제한 |
| **Base Sepolia** | Base의 테스트넷. 진짜 노드·진짜 번들러·진짜 블록 탐색기, 돈만 가짜 | 통합 테스트, 스파이크 | 무료(faucet / 페이마스터 스폰서) |
| **Base 메인넷** | 운영 | Phase 2 | 우리가 페이마스터에 예치 |

## 2. 작동 원리 — 필요한 만큼만

### 2.1 계정, 트랜잭션, 블록
- **계정** = 개인키 하나. 주소(`0x…` 20바이트)는 공개키에서 나온다. 서명은 개인키로, 검증은 누구나.
- **트랜잭션** = "이 계정이 이 컨트랙트의 이 함수를 이 인자로 호출한다"에 서명한 것.
- **블록** = 트랜잭션 묶음. Base는 2초마다 하나. 각 블록은 이전 블록의 해시를 포함하므로 과거 블록을 바꾸면 그 뒤 전부가 깨진다 — 이것이 "체인".

### 2.2 스마트 컨트랙트와 상태
- **컨트랙트** = 체인에 올려 둔 프로그램 + 그 프로그램만 바꿀 수 있는 저장소. 우리 `AccessPolicy`는 "소유자 서명이 맞고, nonce가 안 쓰였고, 만료 전이면 grant를 기록한다"는 규칙 자체다. 배포 후에는 우리도 규칙을 우회할 수 없다(업그레이드는 Timelock 뒤에서 공개적으로만).
- **이벤트(로그)** = 컨트랙트가 남기는 기록. `Granted`, `Opened`, `Revoked`. 블록 탐색기·Agent가 구독한다. 이것이 감사 로그다.
- **읽기는 공짜, 쓰기는 가스** — `isValid(grantId)` 조회는 어떤 노드에나 물어보면 되고 수수료가 없다. 상태를 바꾸는 `grant`, `revoke`만 트랜잭션이고 가스를 낸다.

### 2.3 왜 "못 고치나": L2 롤업의 원리
1. Base 시퀀서(Coinbase 운영)가 트랜잭션을 받아 2초마다 블록을 만든다. — 이 시점에 우리 UX는 이미 끝난다(소프트 확정).
2. 시퀀서는 그 블록들을 압축해 **이더리움 L1에 데이터로 기록**한다(수 분 간격). 이제 데이터는 이더리움의 수천 노드에 복제된다.
3. 누구나 그 데이터를 내려받아 **같은 계산을 다시 실행**해 상태를 재구성할 수 있다. 시퀀서가 결과를 속이면 사기 증명(fault proof)으로 뒤집힌다.
4. 그래서 시퀀서도, Coinbase도, 우리도 **이미 L1에 기록된 승인·회수를 지우거나 바꿀 수 없다**. "우리를 믿어라"가 아니라 "이더리움을 믿어라"가 된다.

우리 정책: `strict_onchain`이 아닌 파일은 1단계(2초)에서 열람을 시작하고, 체인 확인은 백그라운드에서 계속한다(spec §2.6). 엄격 모드만 체인 확정을 기다린다.

### 2.4 가스와 페이마스터
- **가스** = 트랜잭션 수수료. 계산량에 비례하고 ETH로 낸다. 승인 1건(스마트계정 배포 포함) 418,432 gas ≈ Base 메인넷에서 **1센트 미만~수 센트**(시세·혼잡도에 따라 변동).
- **원칙 충돌**: 사용자가 ETH를 사서 넣어야 하면 "아무것도 몰라도 된다"가 깨진다.
- **페이마스터** = "이 사용자 수수료는 내가 낸다"고 서명하는 컨트랙트(ERC-4337). 사용자 계정 잔고 0이어도 통과. 우리가 운영비로 예치해 둔다(`Z-1.H.9`). 페이마스터가 막히면 자체 예치 + EntryPoint 직접 호출로 폴백(T21, 둘 다 실측 완료).

### 2.5 패스키에서 체인까지 (소유자가 "허용"을 누르면)
```
Windows Hello 생체 인증
  → 패스키(P-256)가 승인 내용(EIP-712 AccessGrant)에 서명
  → 소유자 스마트계정(Kernel v3.1, 패스키가 곧 소유권)의 UserOperation 생성
  → 번들러(Pimlico)가 묶어서 EntryPoint 컨트랙트에 제출, 페이마스터가 가스 대납
  → EntryPoint가 WebAuthn 검증기로 패스키 서명 확인(P-256 프리컴파일)
  → 우리 AccessPolicy.grant() 실행 → Granted 이벤트
  → Bob의 Agent가 isValid(grantId)를 읽고(무료) 세션 시작
```
사용자가 보는 건 첫 줄뿐이다. 나머지는 2~5초 안에 시스템이 한다.

## 3. 체인에 올라가는 것 / 올라가지 않는 것

| 컨트랙트 | 저장하는 것 | 위협 |
|---|---|---|
| `FileRegistry` | `fileId`(솔트 해시) → 소유자 계정, 헤더 해시, 버전 | T02 정책 변조, T19 다운그레이드 |
| `AccessPolicy` | grant 기록(권한·만료·횟수), 소유자 nonce, 요청 nonce, revoke 플래그 | T03 재전송, T15 만료, T20 회수 |
| `AuditLog`(Z-1.H.3) | 이벤트만 | T07 추적 |

**절대 올라가지 않는 것**: 파일 내용, 파일명, DEK, 사람 이름·이메일, 기기 공개키 원문(해시만). 체인은 공개이므로 올라간 것은 영구 공개다(T13).

## 4. 테스트하고 이용하는 방법 — 4단계

### 4.1 단위 테스트 (컨트랙트 규칙 자체)
```
cd contracts && forge test
```
18개. 이름에 T-ID가 붙은 것(`test_t03_*`, `test_t14_*`…)이 위협 대응 검증이다. 체인이 필요 없다(Foundry 내장 EVM).

### 4.2 로컬 체인 시나리오 데모 (블록·트랜잭션·이벤트를 눈으로)
```
tools/chain-demo.sh            # Anvil 자동 시작 → 시나리오 실행 → 증거 출력 → 종료
tools/chain-demo.sh --keep     # Anvil을 켜 둔 채 cast로 직접 조회
```
`contracts/script/Demo.s.sol`이 다음을 순서대로 실제 트랜잭션으로 보낸다:
1. 컨트랙트 2개 배포
2. Alice가 파일을 봉인하고 헤더 해시를 등록
3. Alice가 "읽기전용·1시간·2회"를 EIP-712로 서명 → `grant()` → `isValid == true`
4. Bob이 `isValid` 확인 후 `consumeOpen()`
5. 같은 서명을 다시 제출 → **거부**(nonce 소비됨, T03)
6. Alice가 `revoke()` → `isValid == false`

끝나면 스크립트가 `cast`로 블록 수, 이벤트 목록, 마지막 트랜잭션 영수증을 보여 준다. 여기서 보이는 것이 Base 메인넷에서 블록 탐색기로 보게 될 것과 같은 데이터다.

### 4.3 진짜 네트워크 (Base Sepolia)
이미 두 가지 경로가 실측되어 있다(`docs/research/aa_passkey_spike.md`):
- **포크 테스트**: `cd spikes/aa-passkey && forge test --fork-url https://sepolia.base.org` — Base Sepolia의 실제 상태를 복제해 실제 EntryPoint·Kernel 컨트랙트로 UserOp 실행. 키·돈 불필요.
- **실제 제출**: `node --env-file=.env scripts/kernel-account.mjs --send` — 패스키 → 스마트계정 → Pimlico 번들러 → 체인. 결과는 블록 탐색기에서 누구나 본다:
  https://sepolia.basescan.org/tx/0x8e64a7f1652167388e8b5da52422596086a29a043aaef9aca4a1e313f4ca340c
  탐색기에서 볼 것: `Status: Success`, `From`(번들러), `To`(EntryPoint `0x0000000071727De22E5E9d8BAf0edAc6f37da032`), `Logs` 탭의 `UserOperationEvent`, 가스.

우리 컨트랙트를 Base Sepolia에 올리는 것은 `Z-1.H.4`(배포 스크립트 + 주소 파일). 그 전까지 데모는 Anvil로 한다.

### 4.4 E2E (Phase 1, `Z-1.Q.1`)
Windows VM 2대 + Anvil + Relay: 봉인 → 요청 → 승인 → 열람 → 재봉인 → 회수를 자동화.

## 5. 직접 만져 보기 (cast 치트시트)
`tools/chain-demo.sh --keep` 후:
```
cast block-number --rpc-url http://127.0.0.1:8545                     # 지금 블록 높이
cast block latest --rpc-url http://127.0.0.1:8545                      # 최신 블록 내용
cast call <AccessPolicy> 'isValid(bytes32)(bool)' <grantId> --rpc-url http://127.0.0.1:8545
cast logs --address <AccessPolicy> --from-block 0 --rpc-url http://127.0.0.1:8545   # 이벤트 전부
cast tx <txHash> --rpc-url http://127.0.0.1:8545                       # 트랜잭션 원문
```
주소·grantId는 `contracts/out/demo.json`에 있다. Base Sepolia에 대해서는 `--rpc-url https://sepolia.base.org`로 같은 명령이 그대로 된다(읽기는 무료).

## 6. 운영에서 우리가 관리하는 것 / 하지 않는 것

| 관리한다 | 관리하지 않는다 |
|---|---|
| 컨트랙트 배포·업그레이드 키(UUPS + Timelock, `Z-1.H.4`) | 노드, 합의, 블록 생성 |
| 페이마스터 예치 잔고와 스폰서 정책(`Z-1.H.9`) | 시퀀서 가동 |
| RPC/번들러 제공자 계약(Pimlico 등, 복수) | 이더리움 L1 |
| 이벤트 모니터링·알림(`Z-2.H.1`) | |

## 7. 자주 나오는 질문
- **체인이 멈추면?** Base 시퀀서 장애 시 쓰기가 지연된다. 읽기는 다른 RPC로 계속된다. `strict_onchain`이 아닌 파일은 Relay의 서명된 GrantMsg만으로 열리고 체인 기록은 재시도된다(T16, T21).
- **우리가 직접 체인을 운영하면?** 검증자가 우리뿐이면 "못 고친다"가 사라져 DB와 같아진다. ADR-0005 재확인(2026-09-19)에서 기각.
- **개인정보는?** 해시와 커밋만. 그래도 공개 체인이므로 패턴 분석은 가능하고, Phase 3에서 ZK로 강화(T13).
- **비용은 누가?** 소유자 승인 1건 = 우리가 페이마스터로 대납. Bob은 트랜잭션을 보내지 않는다.

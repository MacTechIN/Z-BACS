## 1. 디자인 소스와 우선순위

| 소스 | 성격 | Z-BACS 적용 |

## 3. Z-BACS 상태 ↔ 시각 언어 매핑

| Z-BACS 상태 | 은유 | 색 | 아이콘 | 태그 문구(예) |
|---|---|---|---|---|
| 봉인됨(Sealed) | 닫힌 금고 | close 초록 | 자물쇠 방패(초록) | "잠겨 있어요" |
| 승인 대기(Requesting) | 회전하는 진행 링 | sub 연보라 + process 그라데이션 | 시계 | "승인을 기다리는 중…" |
| 열람 중(Active/ReadOnly) | 열린 금고 | open 주황 | 열린 자물쇠 방패(주황) | "보는 중 · 1시간 남음" |
| 편집 중(Active/Edit) | 열린 금고 + 편집 | open 주황 | 폴더-연필 | "편집 중 · 저장하면 다시 잠겨요" |
| 재봉인 중(Resealing) | 금고 닫히는 전환 | process | 진행 링 | "다시 잠그는 중…" |
| 거부/회수(Denied/Revoked) | 경고 삼각형 | error 빨강 | 경고 | "열 수 없어요 · 보낸 사람이 거절했어요" |
| 실패(Failed) | 경고 | error | 느낌표 원 | "이 파일은 변경되어 열 수 없어요 [다시 요청]" |

- 금고 **열림/닫힘 크로스페이드**(키트 06)는 개봉·재봉인의 핵심 피드백이다. 승인 순간 닫힌 금고 → 열린 금고, 저장·종료 시 그 반대.
- 키트의 "비밀번호 확인 필요/등록됨" 태그와 숫자 키패드는 **패스워드리스 원칙과 충돌**하므로 Z-BACS에서는 "생체인증으로 확인" 흐름으로 대체한다. 키패드 컴포넌트는 복구 코드 입력(2단계) 같은 예외 화면에만 쓴다.

## 4. 컴포넌트 골격 (키트 04·05 기준)

| 컴포넌트 | 변형 | 규칙 |
|---|---|---|
| Button | Primary(다크 네이비 채움 / 라이트 윤곽), OK(파랑 그라데이션), Error(빨강 그라데이션 / 연빨강 채움) | 높이 ≥ 48px, 라운드 12px, 한 화면에 OK 1개. 라벨은 동사("열기", "보내기", "허용") |
| Icon button | 원형 파랑 체크, 네이비 X, 연보라 X, 빨강 느낌표 | 44px 이상, 툴팁 필수 |
| Toggle | OPEN(주황) / CLOSE(초록) | "편집 허용" 같은 이진 정책에만 사용 |
| Status tag | error / success / open / closed / waiting | 점(·) + 짧은 문장. 색만으로 의미 전달 금지(문구 동반) |
| Category chip | App / System / Files | 감사 로그 필터 |
| Progress ring | 열린 호(로딩), 닫힌 링(진행률) | process 그라데이션 |
| Shield icons | 체크(안전), 자물쇠 주황(열림), 자물쇠 초록(잠김), 경고, 전원 | 파일 아이콘 배지와 트레이 아이콘에 재사용 |
| Vault illustration | 열림 / 닫힘 | 홈·열람 화면의 주인공 요소 |

## 5. 화면 골격 (MVP, Windows Agent)

모든 화면은 **텍스트 입력 없음, 기술 용어 없음**([ux_principles.md](../ux_principles.md) §3)을 전제로 한다.

| # | 화면 | 구성 | 주요 컴포넌트 |
|---|---|---|---|
| S1 | 첫 실행(온보딩) | 닫힌 금고 일러스트 + H2 "내 파일을 잠글 준비가 됐어요" + OK 버튼 "시작하기" | Vault, OK Button |
| S1b | 승인 방식 선택 (Z-1.U.7, ADR-0006) | H2 "누군가 파일을 열려고 하면" + 카드형 버튼 2개: "얼굴이나 지문으로 확인하고 승인" / "이 기기에서 바로 승인". 가능한 쪽에 **추천** 칩, 불가능한 쪽은 비활성 + 이유 한 줄 | Choice card, Status tag |
| S1c | 준비 중 → 준비 끝 | 진행 링 하나 + "준비하고 있어요" → 열린 금고 + "준비 끝" + 선택 요약. 이 컴퓨터의 한계(보안 칩 없음, 보관함 없음)만 주의 문구로 1~2줄 | Progress ring, Vault, Notes |
| S1d | 준비 불가 | 경고 + 한 문장 + [다시 시도] 버튼 1개 | Error tag, Button |
| S2 | 홈(트레이 창) | 최근 파일 리스트(상태 태그), 하단 "파일 잠그기" OK 버튼, 우상단 "내 기기" | Status tag, Button |
| S3 | 잠그기(Seal) | 드롭 영역 + 파일명 + [읽기만] [편집 허용] 토글 + OK "잠그고 보내기". "고급" 접힘(유효시간·횟수) | Toggle, Button, Chip |
| S4 | 열기 요청 중 | 열린 호 진행 링 + "OOO님의 승인을 기다리는 중…" + 보조 "취소" | Progress ring, Primary-light |
| S5 | 승인 요청(소유자) | 요청자·파일·권한 요약 카드 + [읽기만] [편집] OK 버튼 2개 + Error-light "거절" | Card, Buttons |
| S6 | 열람 중 상태 | 열린 금고 + 남은 시간 + "저장하면 다시 잠겨요" 태그 + "지금 잠그기" | Vault(open), Status tag(open) |
| S7 | 다시 잠기는 중 → 완료 | 크로스페이드 후 닫힌 금고 + success 태그 | Vault animation |
| S8 | 오류 | 경고 아이콘 + 한 문장 + 행동 버튼 1개 | Error tag, Button |
| S9 | 내 기기 / 복구(2단계) | 기기 카드 리스트 + "기기 추가" | Card, Chip |
| S10 | 기록(감사 로그) | 카테고리 칩 필터 + 시간순 리스트 | Chip, Status tag |

레이아웃: 트레이 창 기본 폭 420px, 다이얼로그 480px, 모바일 승인 앱은 390px 우선(올리브 가이드의 브레이크포인트 채택). 다크/라이트 모두 지원(키트에 두 모드 모두 존재).

## 6. 문구·접근성 규칙 (올리브 가이드에서 채택)
- 큰 글자(본문 16px 이상), 명확한 대비(WCAG AA), 터치 영역 44px 이상.
- 톤: 따뜻하고 쉽고 부담 없게. 평가받는 느낌·복잡한 업무용 폼·전문 용어 금지.
- 문장은 짧게, 주어는 "파일"과 "사람". 예: "민수님이 report.docx를 보고 싶어 해요."
- 색만으로 상태를 전달하지 않는다(아이콘 + 문구 동반).

## 7. 구현 규칙
1. 색·폰트·간격·라운드는 `packages/design-tokens/tokens.css`의 변수만 사용한다.
2. 컴포넌트는 `apps/agent/src/ui/` 아래 §4 목록의 이름으로 만들고, 스토리북(또는 Tauri 데모 창)에서 키트 이미지와 나란히 비교한다.
3. 새 화면은 §5 표에 먼저 행을 추가하고(Figma 연결 시 Figma에 먼저), 그다음 구현한다. Figma는 아직 연결 전이므로(Z-1.U.0) S1b~S1d는 이 표가 원본이고, Figma 연결 시 이 네 화면을 먼저 올린다.
6. UI 문자열과 금지 용어는 [ui_strings.md](ui_strings.md)가 원본이며 `tools/ux-lint.sh`가 CI에서 강제한다.
4. `approx.`로 표시된 토큰 값은 Figma 원본 연결 후 정확한 값으로 교체한다.
5. PR에는 해당 화면 스크린샷과 키트 참조 이미지를 함께 첨부한다.

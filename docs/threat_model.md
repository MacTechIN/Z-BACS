## 1. 자산

## 2. 신뢰 경계

- TB1: 소유자 기기 ↔ 네트워크
- TB2: 수신자 기기 ↔ 네트워크
- TB3: Relay(무신뢰) ↔ 양측 Agent
- TB4: 체인(공개) ↔ Agent
- TB5: 수신자 기기 내부: Agent 프로세스 ↔ 열람 앱 프로세스 ↔ 기타 프로세스

## 5. 잔여 위험 (명시적 수용)

| 위험 | 이유 | 완화 방향 |
|---|---|---|
| 승인받은 수신자의 아날로그 유출 | 소프트웨어 한계 | 워터마크·감사 기록, 법적 고지 |
| 관리자 권한 공격자의 메모리 접근 | OS 신뢰 경계 | Phase 3 TEE, 하드웨어 격리 |
| 변조된 Agent | 클라이언트 신뢰 문제 | 원격 어테스테이션(3단계), 최소 TTL |

## 6. 보안 검증 계획

- 위협 ↔ 태스크 ↔ 테스트 매핑은 `dev_plan.md` 부록 A가 단일 원천. 보안 테스트 이름에 T-ID를 붙인다(`t03_`, `test_t14_`).

- 단위: 암호 테스트 벡터, 헤더 변조 테스트, 티켓 재전송 테스트.
- 퍼징: `cargo-fuzz` 컨테이너 파서, Foundry 퍼즈 테스트.
- 포렌식: 세션 종료 후 디스크 이미지에 원본 문자열 검색 자동화(Windows VM).
- 컨트랙트: Slither, Echidna 불변식("승인 없는 grant 불가", "회수 후 isValid=false"), HF 모델 리포트.
- 외부: MVP 이후 제3자 침투 테스트.

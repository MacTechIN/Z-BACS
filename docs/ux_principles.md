## 1. 원칙 선언

> 최종 결과물은 **사용자가 블록체인, 암호화, 키, 지갑, 계정, 설정, 설치 절차 중 어느 것도 모르고, 배우지 않아도** 파일을 봉인하고, 전달하고, 승인하고, 열 수 있어야 한다.
> 복잡한 등록·절차·환경설정은 **전부 시스템이 대신** 한다. 사용자에게 보이는 것은 "파일", "보내기", "승인/거부", "열기"뿐이다.

## 2. 사용자가 알아야 하는 것의 총량 = 0

| 사용자가 몰라도 되는 것 | 시스템이 대신 하는 방법 |
|---|---|
| 블록체인·지갑·가스·트랜잭션 | 계정은 첫 실행 시 자동 생성(패스키 스마트계정), 가스는 페이마스터 대납, 체인 용어는 UI에 절대 노출 안 함 |
| 개인키·시드 문구·백업 | 키는 기기 생체인증(Windows Hello 등)에 묶여 자동 생성. 복구는 "다른 기기 추가" 또는 "복구 코드 저장" 한 번의 안내로 처리 |
| 암호화·DEK·HPKE·서명 | 완전 내부 동작. 사용자에게는 "잠김/열림" 상태만 표시 |
| 설치 절차·환경설정 | 수신자는 파일을 더블클릭하면 필요한 것이 자동 설치·실행. 설정 화면은 기본값으로 완결, 고급 설정은 숨김 |
| 계정 등록 | 이메일·비밀번호·가입 절차 없음. 첫 실행 → 생체인증 한 번 → 끝 |
| 승인 방식 | 알림 한 개: "OOO님이 report.docx를 열려고 합니다 [읽기만] [편집] [거부]" |
| 저장 후 재암호화 | 자동. 사용자는 평소처럼 저장하고 닫으면 된다 |
| 파일 형식·확장자 | 봉인 파일은 원래 아이콘 + 자물쇠 배지로 표시, 더블클릭으로 열림 |

## 3. 설계 규칙 (필수)

1. **첫 실행 3단계 이내**: 설치 → 생체인증 1회 → 사용 시작. 입력 폼 없음.
2. **텍스트 필드 금지 원칙**: 온보딩·봉인·승인 흐름에서 사용자가 문자를 입력해야 하는 화면은 만들지 않는다. (파일명 변경 등 선택 사항은 예외)
3. **기술 용어 금지**: UI 문자열에 블록체인, 지갑, 키, 트랜잭션, 가스, 서명, 해시, 노드, 컨트랙트, HPKE, DEK, CID 등을 쓰지 않는다. 대신 "잠금", "승인", "열기", "보내기", "내 기기".
4. **기본값으로 완결**: 정책(읽기전용·1시간·1회)은 기본값으로 동작하며, 봉인 시 선택은 [읽기만] [편집 허용] 두 버튼 수준이다.
5. **수신자 무설치 경험**: 수신자는 계정도 앱도 없이 시작한다. 파일을 열면 필요한 것이 자동으로 준비되고, 첫 열람까지 클릭 3회 이내.
6. **오류는 행동으로 안내**: "서명 검증 실패" 대신 "이 파일은 변경되어 열 수 없습니다. 보낸 사람에게 다시 요청하세요 [요청 보내기]".
7. **기다림은 숨긴다**: 체인 확정·키 교환 등 지연은 진행 표시 하나로 통합. 사용자가 지연의 원인을 알 필요 없다.
8. **복구는 미리, 조용히**: 기기 2대째 등록 또는 복구 코드 저장을 온보딩 후 적절한 시점에 한 번만 제안. 거절해도 사용 가능.
9. **고급 기능은 접어 둔다**: 셀프호스팅 Relay, strict 온체인 모드, 정책 세부 조정은 "고급" 뒤에 숨긴다.
10. **오프라인·실패도 설계 대상**: 소유자가 오프라인이면 "승인 대기 중, 응답 오면 알려드릴게요"로 처리하고 사용자가 할 일을 남기지 않는다.

## 4. 기술 결정에 미치는 영향

| 영역 | 이 원칙이 강제하는 선택 |
|---|---|
| 계정 | ERC-4337/7579 패스키 스마트계정 + 페이마스터. EOA·시드 문구·MetaMask 연동 금지 (ADR-0005) |
| 인증 | 기기 생체(Windows Hello/Touch ID) 우선. BSA도 사용자에게는 "생체인증"으로만 보임 (ADR-0003) |
| 배포 | Windows 자체실행 래퍼(`zbacs-stub.exe`)를 2단계가 아니라 **1단계 후반으로 앞당김**. 수신자 무설치 경험이 핵심 |
| 설치 | 무인 설치, 자동 업데이트, 파일 연결 자동 등록 |
| 정책 UI | 봉인 다이얼로그 = 버튼 2개 + "보내기" |
| 승인 UI | 푸시 알림에서 바로 승인 가능(알림 액션 버튼) |
| Relay | 기본 호스팅 Relay 제공. 사용자는 서버 주소를 입력하지 않는다 |
| 키 복구 | 소셜 복구·다중기기를 "내 기기" 목록으로 표현 |

## 5. 완료 기준 (UX Definition of Done)
각 릴리스는 아래 테스트를 **매뉴얼·설명 없이** 통과해야 한다.

| 테스트 | 기준 |
|---|---|
| U-1 신규 소유자 | 처음 보는 사용자가 설명 없이 3분 내 파일 1개 봉인 후 전송 |
| U-2 신규 수신자 | 앱 없는 PC에서 `.zbacs` 파일 받은 사용자가 설명 없이 3분 내 열람 요청까지 도달 |
| U-3 승인 | 소유자가 알림에서 10초 내 승인/거부 |
| U-4 편집 저장 | 수신자가 편집 후 평소처럼 저장·닫기만으로 재봉인 완료(추가 조작 0) |
| U-5 용어 검사 | UI 문자열 전수 검사에서 금지 용어 0건 (CI lint) |
| U-6 입력 검사 | 온보딩·봉인·승인·열람 흐름에서 텍스트 입력 필드 0개 |

## 6. 디자인 소스: Figma 디자인 가이드 (Single Source of Truth)

- 모든 UI(Agent 데스크톱, 승인 앱, 설치기·스텁 화면, 웹 대시보드)는 **Figma의 Z-BACS 디자인 가이드**를 원본으로 삼는다. 코드는 그 가이드에서 생성·파생하며, 코드에서 임의로 색·간격·컴포넌트를 만들지 않는다.
- 작업 절차: (1) Figma MCP로 디자인 가이드 파일을 연다 → (2) 변수(색·타이포·간격)와 컴포넌트를 가져온다(`get_variable_defs`, `get_design_context`) → (3) 디자인 토큰을 `apps/*/src/design/tokens.*`로 생성한다 → (4) 화면은 해당 프레임의 `get_design_context` 결과를 기준으로 구현한다 → (5) 구현 후 `get_screenshot`과 비교한다.
- 가이드에 없는 화면이 필요하면 코드 먼저가 아니라 **Figma에 먼저 추가**(`use_figma`)하고 그 다음 구현한다.
- Code Connect(`add_code_connect_map`)로 Figma 컴포넌트 ↔ 코드 컴포넌트를 매핑해 두고 드리프트를 막는다.
- Figma 파일 링크와 파일 키는 [reference/figma.md](reference/figma.md)에 기록한다.

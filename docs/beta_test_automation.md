## 0. 기준: 테스터가 알아야 할 것이 0이어야 한다

일반인 테스트의 정의 = 참가자가 받는 안내가 **"이 파일을 내려받아 실행하고, 화면이 시키는 대로 하세요"** 한 줄이어야 한다. `cargo`, `node`, 터미널, 지갑, 테스트넷 ETH, 서버 주소, 설정 파일 중 하나라도 나오면 실패다(ux_principles §2, U-1·U-2).

지금은 이 기준에서 **모든 것이 개발자 절차**다: 저장소 clone → `tools/setup.ps1` → `cargo tauri build` → Relay를 `cargo run` → 체인은 Anvil. 아래는 이것을 층별로 없애는 계획이다.

## 1. 다섯 층과 가능 여부

| 층 | 테스터가 지금 해야 하는 일 | 자동화 후 | 가능 여부 | 비용 | 막는 것 |
|---|---|---|---|---|---|
| **L1 설치** | Rust·Tauri 툴체인 설치, 빌드 | 설치 파일 1개 다운로드 → 더블클릭 | **지금 가능** | CI 잡 1개 (~0.5세션) | 코드 서명 없음 → SmartScreen 경고 1회("추가 정보 → 실행"). 닫힌 베타에서는 안내 한 줄로 감수(Z-1.S.2 보류 방침) |
| **L2 서버** | Relay 직접 실행, Anvil 실행, 컨트랙트 배포 | 아무것도 안 함. Agent에 Relay 주소·체인 주소가 내장 | **지금 가능** | Docker(Z-1.R.4) ~0.5세션 + Base Sepolia 배포 1회 + 호스팅 | **호스팅 계정**(사용자 결정: 무료 VPS/컨테이너 서비스 1개). 테스트넷 가스는 faucet + 페이마스터 스폰서로 0원 |
| **L3 기능** | (없음 — 아직 없는 기능은 테스트 불가) | A(잠그기)→B(요청·승인)→C/D(열람·저장)→E(회수) 전부 | **베타 컷 코드 후** | G.9→G.10→G.11→G.12→U.4→U.5 (dev_plan §1.9, 2~3세션) | 오늘 테스트 가능한 범위: 설치·첫 실행·잠그기까지 |
| **L4 테스트 진행** | 두 대의 PC와 두 사람, 절차서 읽기 | **체험 모드**: PC 1대에서 버튼 1개로 A~E를 순서대로 겪게 함. **결과 보내기** 버튼 1개로 보고 완료 | **L3 후 가능** | ~1세션 | 없음 (설계는 §2) |
| **L5 무인 E2E** | — (팀용) | CI에서 사람 없이 A~E 검사 | **소프트웨어 서명기로만 가능** | Z-1.Q.1 | **Windows Hello 생체 인증은 원리상 자동화 불가**(사용자 제스처가 보안 경계). 실제 Hello 경로는 사람이 한 번은 눌러야 한다 → `zbacs-wincheck`가 그 "한 번"을 2분으로 줄인 것 |

요약: **L1·L2는 지금 시작할 수 있고 L3와 독립**이다. L4는 L3가 끝나야 의미가 있다. L5는 팀 내부용이며 일반인 테스트와 무관하다.

## 2. L4 설계 — 체험 모드 (ux_principles §6 체크리스트 적용)

**문제**: 시나리오 B는 소유자와 수신자, 두 기기가 필요하다. 일반인 한 명에게 "친구 PC를 빌려라"는 요구는 U-1·U-2 위반이다.

**해법**: Agent에 "체험해 보기" 버튼 하나. 누르면 같은 PC에서 두 역할을 순서대로 겪는다. 네트워크·서명·체인 경로는 **전부 실제**이고(Relay 왕복, 패스키 서명, 체인 기록), 다른 것은 "수신자 기기"가 같은 PC의 두 번째 기기 프로필이라는 점뿐이다.

| 단계 | 화면이 하는 일 | 테스터가 하는 일 | 검사되는 시나리오 |
|---|---|---|---|
| 1 | 샘플 문서(`체험용 메모.txt`)를 만들어 잠근다 | [체험해 보기] 클릭 | A |
| 2 | 그 파일을 "다른 기기"로서 연다 → 승인 요청이 Relay를 거쳐 돌아온다 | 없음 (자동) | B-1~3 |
| 3 | 승인 알림이 뜬다: [거부] [읽기만] [편집 허용] | 하나 선택 → Windows Hello | B-4~5, U-3 |
| 4 | 파일이 기본 앱으로 열린다(읽기만이면 읽기전용) | 한 줄 적고 저장·닫기 | C 또는 D, U-4 |
| 5 | "지금 회수해 보세요" [회수] | 클릭 → 열려 있던 앱이 닫히고 재봉인 | E |
| 6 | 결과: 5단계 체크 표시 + [결과 보내기] | 클릭 (보낼 내용을 먼저 보여 준다) | — |

- 입력 필드 0개(U-6), 기술 용어 0개(U-5, `tools/ux-lint.sh`가 검사).
- **결과 보내기**가 보내는 것: `zbacs-wincheck` PASS/FAIL, 단계별 성공·소요 시간, 오류 코드, OS 버전. **보내지 않는 것**: 파일 내용, 파일명, 키, 계정 주소, 사람 식별 정보. 보내기 전에 전문을 화면에 보여 주고 동의를 받는다(T13 원칙 적용).
- 두 번째 기기 프로필은 체험 모드 전용으로 격리하고, 끝나면 지운다 — 실제 기기 키와 섞이지 않는다.

## 3. 실행 순서 제안

| 순서 | 작업 | 태스크 ID(제안) | 의존 |
|---|---|---|---|
| 1 | CI `release` 잡: `cargo tauri build --bundles nsis`를 windows-latest에서 실행, GitHub Release에 설치 파일 첨부. `zbacs-wincheck.exe`도 함께 | **Z-1.S.3** — `.github/workflows/release.yml` (2026-09-21) | 없음 — 지금 |
| 2 | Relay Docker + 호스팅, Base Sepolia에 컨트랙트 배포(Z-1.H.4 스크립트 사용), Agent에 기본 주소 내장 | Z-1.R.4 + **Z-1.H.11**(신설: 기본 엔드포인트 내장) | 호스팅 계정(사용자) |
| 3 | 베타 컷 코드 G.9 → G.10 → G.11 → G.12 → U.4 → U.5 | 기존 | — |
| 4 | 체험 모드 + 결과 보내기 | **Z-1.G.14**(신설), **Z-1.Q.5**(신설) | 3 |
| 5 | 참가자 5명 닫힌 베타 = Z-1.U.6 사용성 테스트 | 기존 | 1~4 + Windows 실기 확인 |

1과 3은 병렬이다. 2는 호스팅 결정만 나면 1과 같이 갈 수 있다.

## 4. 솔직한 한계

- **Windows 실기 확인은 여전히 사람이 먼저 해야 한다.** 일반인에게 배포하기 전에 `docs/windows_checklist.md` §1~§4가 한 번은 통과해야 한다. 자동화는 이 확인을 대신하지 못하고, 확인 뒤에 *반복*을 없앨 뿐이다.
- 코드 서명 없이 배포하면 참가자 PC의 보안 소프트웨어가 설치를 막을 수 있다. 닫힌 베타(아는 사람 5명)에서는 감수하고, 공개 배포 전에 Z-1.S.2를 다시 본다.
- 체험 모드는 "두 사람 사이"를 시뮬레이션한다. 실제 두 기기 테스트(U-2, 무설치 스텁 Z-1.S.1)는 베타 이후 별도 라운드다.

## 5. 결정이 필요한 것

1. **호스팅**: Relay 한 대를 어디에 둘지(무료 컨테이너 서비스 계정 1개 필요, 사용자만 만들 수 있음). 결정 전까지는 L2를 "Agent 안에 내장 Relay를 같이 띄우는 로컬 모드"로 대체해 체험 모드까지는 가능하게 할 수 있다(단, 2대 테스트는 불가).
2. **순서**: L1(설치 파일 CI)을 지금 G.9보다 먼저 할지. 제안은 **L1 먼저(0.5세션)** — 그래야 Windows 실기 확인도 `cargo` 없이 설치 파일로 할 수 있어, 사용자 차례인 그 확인이 빨라진다.

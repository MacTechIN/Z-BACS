# ADR-0005: EVM L2(Base) + 로컬 Anvil, 소유자 = 패스키 스마트계정

- 상태: Accepted (2026-09-18), **재확인 (2026-09-19, Z-0.H.2 이후)**

## 결정
- 개발: Foundry Anvil. 테스트넷: Base Sepolia. 운영: Base(또는 RIP-7212 지원 OP Stack 체인). 프라이빗 배포 옵션: Hyperledger Besu.
- 소유자 계정: ERC-7579 Kernel + 패스키(WebAuthn) 검증 모듈, 페이마스터 가스 대납(Pimlico).
- 컨트랙트: OpenZeppelin v5, UUPS + Timelock.

## 근거
- L2는 승인 왕복 지연을 초 단위로 유지한다(보고서 §6.2).
- RIP-7212 P-256 프리컴파일로 패스키 서명 온체인 검증 가스가 낮다. (2026-09-19 실측: Base Sepolia·메인넷 활성, 3,885 gas vs Solidity 폴백 334,897 — `docs/research/aa_passkey_spike.md`)
- 감사 로그·회수·정책 앵커는 EVM 이벤트로 충분하다.

## 대안
- 자체 하이브리드 DLT(BSA 방식) / 자체 프라이빗 체인 — 운영 부담 과다. 검증자가 우리뿐이면 "누구도 못 고친다"는 성질이 사라져 서명된 DB와 다르지 않다. 고객 컨소시엄 노드가 전제될 때만 재검토(Phase 3, Besu).
- 체인 없이 투명성 로그(머클 루트 주기 공개 + 하루 1회 공개 체인 앵커) — 단순하지만 "운영자를 믿어야" 하는 구간이 생기고, 블록체인 기반이라는 제품 정체성과 어긋남. 2026-09-19 기각.
- Solana/Sui — 패스키 지원은 있으나 생태계·AA 도구 성숙도에서 EVM 우위.

## 재확인 (2026-09-19)
- 질문: 페이마스터·번들러 의존이 꼭 필요한가, 자체 체인을 운영하면 안 되는가.
- 결정: **공개 L2(Base) 유지.** 블록체인 기반은 제품의 핵심 가치이고, 그 위의 변조 불가 기록(정책 앵커·nonce·감사 로그)이 목표 달성 수단이다. 둘 다 취한다.
- 가스는 사용자에게 절대 노출하지 않는다(ux_principles). 페이마스터 예치는 서비스 운영비로 흡수(Z-1.H.9). 페이마스터·번들러 장애 시 자체 예치 + EntryPoint 직접 호출로 폴백(T21, Z-0.H.2에서 두 경로 모두 실측).
- 근거 실측: Base Sepolia 실제 제출 418,432 gas(프리컴파일 경로), 페이마스터 스폰서로 계정 잔고 0 — `docs/research/aa_passkey_spike.md` §2b.

## 결과
- `strict_onchain` 정책이 아닌 경우 개봉은 체인 확정을 기다리지 않는다(UX 우선).

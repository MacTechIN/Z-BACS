# BSA SDK 조사 메모 (Z-0.A.3, OR-1)

| 상태 | **대기 중 — 사용자 신청 필요** (2026-09-19) |
|---|---|
| 막힌 이유 | BSA SDK는 상용·비공개다. 공개 저장소·공개 API 문서가 없고, 샌드박스 Client Key를 발급받아야 실제 호출 규격을 알 수 있다. 신청은 조직 명의의 외부 절차라 내가 대신 할 수 없다. |
| 영향 | `BsaProvider`(Z-1.A.5)는 **mock으로 구현**해 두었다. SDK를 받으면 mock을 실제 호출로 바꾸는 것 외에 상위 코드는 바뀌지 않는다(ADR-0003의 어댑터 격리). MVP는 패스키/기기 키(ADR-0006)로 완결되므로 이 항목이 Phase 1을 막지 않는다. |

## 1. 사용자가 해야 할 일

1. **ITU-T DFS(Digital Financial Services) 보안 랩 / X.1284 관련 창구** 또는 BSA 제공사에 샌드박스 Client Key를 신청한다. 신청서에 보통 필요한 항목:
   - 조직명·담당자·연락처
   - 사용 목적: "원격 파일 접근 통제 시스템(Z-BACS)의 소유자 승인 인증에 X.1284 흐름 적용 검증"
   - 연동 환경: 데스크톱 Agent(Windows) + 모바일 승인 앱
   - 예상 호출량: 샌드박스 수준(일 수백 건 이하)
2. 받은 자료 중 **다음 네 가지**를 알려 주면 내가 어댑터를 붙인다:
   - Client Key / Secret 발급 방식과 보관 요구사항
   - 인증 요청 생성 API(엔드포인트·파라미터·응답)
   - 결과 검증 방식(콜백인지 폴링인지, 서명 검증 키를 어디서 받는지)
   - SDK 배포 형태(네이티브 DLL / REST / 모바일 SDK)와 라이선스

**키·시크릿 값 자체는 보내지 말 것.** `.env`나 OS 자격 증명 저장소에 두고, "받았다"는 사실과 위 규격만 알려 주면 된다.

## 2. 지금까지 확인된 것

| 항목 | 내용 | 출처 |
|---|---|---|
| 표준 | ITU-T X.1284 — 모바일 기기를 이용한 다중요소 인증 프레임워크. 요청별 일회용 인증키 파생·폐기 흐름 | 공개 표준 문서 |
| BSA 위치 | 위 표준을 블록체인 기반으로 구현했다고 소개되는 상용 제품군 | 프로젝트 원본 분석 문서 |
| 공개 코드 | 없음(2026-09 기준). GitHub·crates.io·npm에 공식 배포 없음 | 검색 |

## 3. 그동안의 대체 구현

| 태스크 | 상태 |
|---|---|
| `PasskeyProvider` (Z-1.A.2) | Windows Hello 구현 완료, 실기 확인만 대기 |
| `DeviceKeyProvider` (Z-1.A.7) | TPM 구현 완료, 실기 확인만 대기 |
| `BsaProvider` (Z-1.A.5) | **mock 구현** — 인터페이스 호환성만 고정 |
| `OtakProvider` (Z-1.A.6) | X.1284 흐름(요청별 키 파생·폐기)을 자체 구현 예정 |

마케팅·문서에서 "BSA 기반"은 ADR-0003의 정의대로 **"X.1284 표준 흐름 준수 + BSA SDK 연동 가능"**으로 쓴다. SDK 연동이 확정되기 전까지 "BSA 탑재"라고 쓰지 않는다.
